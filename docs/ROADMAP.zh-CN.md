# 路线图

gen-chart 当前具备的功能，以及未来的规划。将项目推进到现阶段的构建计划已停止维护；本文档取而代之。

## 已发布

**四类图表**，每一类均配有带类型的 JSON Schema、确定性的手写 SVG 渲染器，且无运行时依赖。

| 类别 | 标记类型 |
|---|---|
| `cartesian` | 折线图、柱状图、水平发散柱状图、分组柱状图、堆叠柱状图、百分比堆叠图、面积图、堆叠面积图、区间图、柱线组合图、散点图、气泡图 |
| `distribution` | 直方图、箱线图——根据原始观测值计算 |
| `proportion` | 饼图、环形图 |
| `matrix` | 热力图，支持顺序色阶或发散色阶 |

**比例尺。** 线性、时间（UTC 日历刻度）、分类型和对数比例尺。

**诚实性引擎。** 验证器会拒绝数据无法支撑其表达的图表；每一条诊断信息都包含稳定的代码、一个 JSON Pointer 指向的对象、测量证据，以及一组封闭的受支持修复方案：

- 柱状图和面积图的基线必须为零
- 每条坐标轴只能使用一个单位
- 饼图扇区值不得为负，数量必须为 2–7 个，并且总和须与声明的总计一致
- 直方图分箱数量应接近 Freedman–Diaconis 规则的建议值，并在图表中披露
- 对数轴拒绝柱形标记、非正值和 `zero: true`，并会明确标注自身为对数轴
- 堆叠图拒绝负值、混合标记类型和单一系列
- 百分比堆叠图会披露分母的变化，并在工具提示中保留绝对值
- 当数据同时包含正负值时，拒绝使用方向性色彩角色
- 区间带必须明确说明含义、提供成对边界，并满足下界 ≤ 上界
- 水平发散柱状图必须只有一个未堆叠的有符号系列、共享的零基线，以及符号含义稳定的语义颜色
- 散点图和气泡图在可见点超过 2,000 个时发出警告；它们可以仅对渲染标记进行确定性降采样，同时保留全部源数据行
- 顺序热力图色阶拒绝负值；发散色阶必须指定中点
- 用户编写的运维事件可在笛卡尔图表上渲染为带标签的线条或紧凑的顶部条带，并支持语义颜色和日内 UTC 时间戳

**构图检查。** 检查刻度标签碰撞（旋转 → 减少 → 失败）、注释重叠、点密度、堆叠深度、矩阵密度与稀疏度，并通过 CIEDE2000 验证相邻堆叠区段在感知上可区分。

**查看器。** 单个自包含 HTML 文件，可离线使用且不依赖 CDN：支持十字准线工具提示、图例切换、点击聚焦的“数据护照”（Data Passport）及渲染时统计信息、可选择 Classic、Cool、Warm 和 Primary 图表配色的颜色选择器、永不重新缩放 y 轴的可选框选缩放、最多五个预设引导视图、深层链接，以及导出功能（PNG、独立 SVG、溯源 CSV、1200×630 分享卡片）；导出始终捕获静止状态下的规范图表。

**无障碍。** 每张图表都包含一张视觉隐藏的数据表，其中列出精确数值；所有图表类别均支持键盘逐项浏览和实时区域播报；状态提示不只依赖颜色；语义角色颜色和热力图颜色在两种主题下均经过 WCAG AA 验证。

**本地化。** 查看器界面和计算生成的说明支持 `en` 与 `zh-CN`；用户编写的内容永不翻译。

**工具链。** 提供 `validate` / `render` / `deliver`，支持原子提交和 SHA-256 回执；可选生成与同次渲染一致的 PNG 预览，便于在聊天中交付；提供用于路由的 `guide`、用于生成带类型列概况的 `inspect-data`、用于提供包含性证据的 `visual-check`、`demo`、`doctor`、确定性的包构建，以及覆盖 Node 22 和 24 的 CI。

**交互式教学示例库。** 通过一次分阶段、确定性的构建，将全部 17 个示例提升到展示级质量后再替换已发布的网站。首页提供四种智能体的安装命令，并讲解完整的“安装 → 复制提示词 → 带类型的 JSON IR → 交互式图表”工作流。每个示例都通过生成的审计清单，将包含简洁数据的消息提示词、精确的源文件与制品字节、验证计数和 SHA-256 摘要绑定在一起。

## 规划中

以下项目大致按其价值优先级排列。

### 标记类型

- **日历热力图**——按“周 × 星期”排列的全年活动密度网格。它使用不同于矩阵热力图的布局引擎，需要处理日期到单元格的映射、月份边界和不完整周。

### 诚实性

- **双轴。** 当前不支持，`guide` 会对此作出说明。要诚实地支持双轴，需要强制使用不同单位、在图例中标明各坐标轴，并拒绝通过对齐技巧人为制造相关性。
- **点密度聚合。** 目前已发布确定性的渲染器侧降采样；当采样后的点云仍无法清晰表达分布时，仍需在未来实现有意义的分箱或分组。
- **趋势注释。** 如果未来添加拟合线，则必须以确定性方式计算，标注所用方法，并且绝不能让人误以为它是原始数据。

### 覆盖范围

- **`ordinary-model-floor` 基准测试**——包含提示词及预期验证结果，用于证明普通模型仅凭 `SKILL.md` 即可编写有效规范。该项目被有意推迟：它需要模型访问能力才能产出值得信赖的结果，而从未运行过的测试框架不能作为证据。
- **更多语言区域。** i18n 表规模较小，且易于增量扩展；限制因素是能够审核措辞的人员，而非实现机制。

### 易用性

- **通过一个提示词生成多图表制品。** 允许使用一份用户编写的数据集和一个请求生成多个相互协调的图表规范，并将它们组合到一个交互式 HTML 制品中；适当情况下共享事件数据并对齐时间范围。
- **强化可选配色的无障碍能力。** 在保留已批准的三色和六色色组原值的同时，通过经过验证的非颜色边界处理，解决测得的浅色面板对比度问题和相邻系列的 ΔE 差距。
- **数据大小上限。** 已有行数限制；尚未实现按字节限制以及相应的降采样修复方案。
- **`meta.animation: "draw"`**——一次有限时长的折线绘入动画，需主动启用，且不会出现在导出结果中。
- **品牌配色。** 提供显式的 `brand_palette` 以允许原始十六进制颜色，同时仍须通过对比度和相邻颜色检查。

## 不在规划中

以下方案经过评估后已被搁置；它们不属于技术债务。

- **绘图库封装。** 渲染器有意采用手写实现：只有掌控几何计算，才能获得字节级稳定的黄金输出，以及真正理解图表的验证能力。
- **3D、装饰性渐变、仪表盘外壳。** 它们不编码任何信息。
- **实时数据获取、服务器或所见即所得编辑。** 一份规范加一个确定性渲染器就是完整契约。
- **从渲染器中拆出 `collision.mjs` 和 `legend.mjs`。** 这些逻辑规模较小且因图表类别而异；共享模块只会增加间接层，却无法实现复用。
