# Interactive Gallery Instruction Page Plan

**Status:** Implemented

**Target command:** `cd gen-chart && npm run build:gallery`

**Outcome:** Turn the existing generated gallery into a static instruction
page where every example teaches one honest, inspectable workflow:

```text
01 Install skill  →  02 Copy prompt  →  03 Inspect typed JSON IR  →  04 Open checked chart
```

This plan applies the useful parts of Archify's Proof Lab and Start experience
without adding its multi-page navigation or iframe cost. See
[`archify-analysis.md`](archify-analysis.md).

## 1. Product promise and truth boundary

The gallery remains the project homepage. A first-time visitor should be able
to understand the product, copy a useful chart request, inspect the exact IR
that gen-chart accepts, and open the artifact built from that IR without first
reading the schemas or README.

Every example card must expose:

- an inline SVG preview extracted from the delivered artifact;
- one concise, copy-ready message containing the example data;
- the exact checked-in typed JSON IR used by the build;
- the exact self-contained interactive HTML delivered from that IR;
- chart family, mark(s), and the question the chart answers;
- build-derived showcase status and SHA-256 digests.

The relationship between the three stages must be described precisely:

- The checked JSON IR is the source of truth for the published chart.
- The HTML artifact is deterministically delivered from that IR.
- The copy prompt is deterministically reconstructed from authored teaching
  intent plus the IR's data. It shows how to request a comparable result.
- The prompt is **not** historical provenance and cannot promise that an LLM
  will recreate the checked IR byte-for-byte. Do not label it “the prompt that
  generated this chart.”

The page remains static, works on GitHub Pages, requires no service or API,
and sends no prompts, chart data, clipboard contents, or usage events
anywhere.

## 2. Scope

### In the first release

- All 12 checked gallery examples participate.
- One generated page at `docs/index.html` remains the entry point.
- Inline SVG previews remain the default; interactive charts open as separate
  self-contained HTML files.
- Each card adds a copy-ready message, typed-source link, artifact link, and
  generated verification facts.
- The start section covers Cursor, Codex, Claude Code, and OpenCode with the
  same Skill and agent-specific installation commands.
- Family filtering, stable case links, and accessible copy behavior work with
  a small browser script.
- The entire site is regenerated by the existing `build:gallery` command.

### Explicitly out of scope

- Calling an LLM or executing prompts in the browser.
- Editing or compiling JSON in the gallery.
- A separate Start, Guide, or marketing homepage.
- Agent-specific prompt variants; agent choice changes installation commands
  only.
- Iframe-per-card previews, analytics, accounts, or a backend.
- Claiming visual review from automated containment checks.

A single featured iframe can be evaluated later only if user testing shows
that the current exact SVG previews do not communicate interactivity.

## 3. Resolved architecture

The generated site has two authored inputs and one generated evidence record,
with no hand-authored status data:

```text
gallery-cases.mjs ─┬─→ prompt formatter ←─ example JSON IR
                  │          │
                  │          └─→ copy-ready message ──┐
                  └─→ teaching metadata ───────────┤
                                                    │
example JSON IR ─→ showcase deliver ─→ checked HTML ─→ SVG preview ─┤
                                                    │
                                                    └─→ case build record
                                                         ├─→ gallery manifest
                                                         └─→ instruction page
```

Use these files:

| File | Responsibility |
|---|---|
| `gen-chart/examples/gallery-cases.mjs` | Stable case order and authored teaching intent |
| `gen-chart/scripts/gallery-prompt.mjs` | Pure deterministic prompt/data formatting |
| `gen-chart/scripts/gallery-template.html` | Page HTML, CSS, and progressive-enhancement runtime |
| `gen-chart/scripts/build-gallery.mjs` | Registry checks, delivery orchestration, previews, manifest, and staged output |
| `docs/gallery/manifest.json` | Generated audit record for every published case |

Do not add gallery questions or prompts to chart schemas, delivered payloads,
or the skill package. They are teaching metadata, not chart semantics.

## 4. Case registry contract

Create `gen-chart/examples/gallery-cases.mjs`:

```js
export const GALLERY_CASES = [
  {
    id: 'build-times',
    spec: 'build-times.distribution.json',
    question: 'How do build times and outliers differ by pipeline?',
    prompt: {
      request: 'Compare CI build durations by pipeline as a boxplot in seconds.',
      requirements: [
        'Show the raw grouped distributions, whiskers, and outliers.',
        'Explain which pipeline is slowest and most variable.'
      ]
    },
    featured: true
  }
];
```

Registry invariants:

- `id` is unique, stable, lowercase kebab-case, and becomes
  `id="example-<id>"`.
- `spec` is a basename under `gen-chart/examples/`; paths and traversal are
  rejected.
- `question`, `prompt.request`, and every requirement are non-empty authored
  strings.
- `request` contains intent and requested chart behavior, not copied data.
- `requirements` records semantically important choices that raw columns
  cannot express, such as a log scale, annotation, guided view, locale, or
  target line.
- Family, marks, title, locale, units, and display tags are derived from the
  parsed spec rather than repeated in the registry.
- Exactly one case is `featured`.
- Every `*.(cartesian|distribution|proportion|matrix).json` gallery spec is
  registered exactly once, and every registry item resolves to one spec.
- Registry order is page order; filesystem order never controls the product.

Adding an example therefore requires adding its JSON/HTML golden pair and one
registry entry. CI fails on either an unregistered spec or a dangling entry.

## 5. Copy-ready prompt contract

Create `gen-chart/scripts/gallery-prompt.mjs` as a pure module. It accepts a
validated case and parsed spec and returns one LF-normalized string.

Each prompt reads like a message a person would actually send to an agent:

```text
Use gen-chart to <authored request>. <authored requirements>.

unit:        42 45 47 48 50 51 53 55 58 71
integration: 118 124 131 136 140 145 152 158 166 210
e2e:         295 312 328 341 355 370 388 402 425 610
```

Use grouped labelled rows for grouped two-column distributions, one labelled
value list for a single-column distribution, and a compact Markdown table for
ordinary cartesian, proportion, and matrix data. Preserve column order, row
order, `null`, Unicode, labels, units, and date strings. Keep one trailing
newline for stable snapshots and hashes. The exact typed source remains the
next workflow step; the copy-ready prompt must not expose internal IR ceremony.

Prompt rules:

- Do not embed the full expected IR; the typed JSON link is the inspectable
  second stage.
- Do not derive conclusions that are absent from the authored request or
  checked spec.
- Preserve the example language. The `zh-revenue` request and requirements
  remain authored Chinese, including the short gen-chart instruction.
- Escape only when placing prompt text into HTML. The formatter returns plain
  text and must know nothing about the DOM or clipboard.
- Add `promptSha256` to the manifest so tests can bind copied text to the
  generated record.

## 6. Verified build pipeline

`npm run build:gallery` must build from JSON instead of trusting the committed
example HTML as gallery input.

For each registry case:

1. Resolve and parse the registered JSON spec.
2. Assert the filename family matches `spec.chart_type`.
3. Invoke the existing public CLI as a subprocess:

   ```text
   node bin/gen-chart.mjs deliver <family> <spec> <staged-html> \
     --quality showcase --json
   ```

4. Require exit code `0` and parse the JSON receipt. Do not create a second
   implementation of showcase acceptance or renderer selection.
5. Require `ok: true`, `quality: "showcase"`, zero errors, zero warnings, and
   receipt hashes/byte counts that match the staged source and HTML bytes.
6. Run the gallery's small post-delivery structural check: exactly one
   `svg.gc-chart`, parseable `#gc-payload`, no unresolved template/i18n
   placeholders, and no external `src`/`href` dependencies.
7. Compare the staged artifact byte-for-byte with the committed
   `gen-chart/examples/<id>.html` golden. If it differs, fail with the existing
   `npm run render:examples` repair command; never silently bless stale goldens.
8. Extract that artifact's at-rest SVG, remove viewer-only hover layers, and
   apply the existing Classic preview palette transformation.
9. Generate the copy-ready message from the registry entry and parsed IR.
10. Copy the original JSON bytes to `docs/gallery/sources/`; do not parse and
    reserialize them.
11. Record all paths, receipt facts, byte counts, and hashes in the manifest
    entry.

After all cases pass:

12. Serialize `manifest.json` deterministically with registry order, two-space
    indentation, and one trailing newline. Do not include a build timestamp,
    random value, or absolute local path.
13. Render `docs/index.html` from the external template and the same in-memory
    case records used for the manifest.
14. Validate every generated relative link and prompt/card count against the
    staged tree.
15. Commit the complete staged tree to `docs/` as one transaction.

### Failure and commit behavior

The current builder deletes `docs/` before it proves the new build. Replace
that behavior with a staged sibling directory and a transactional directory
swap:

1. create a uniquely named stage directory beside `docs/`;
2. generate and verify the complete tree there;
3. rename existing `docs/` to a backup;
4. rename the stage directory to `docs/`;
5. restore the backup if the second rename fails;
6. remove the backup only after the new tree is in place;
7. clean abandoned stage directories on handled failure.

Validation, rendering, prompt, and link failures must leave the last-good
`docs/` byte-for-byte unchanged. A commit I/O failure must exit non-zero and
attempt rollback. The generated tree always includes `.nojekyll`; replacing
the whole tree ensures removed cases cannot leave stale files behind.

Export the stage-building and commit helpers so failure behavior can be tested
against temporary directories without touching the repository's real docs.

## 7. Manifest contract

Generate `docs/gallery/manifest.json` as an audit interface, not as browser
state:

```json
{
  "schemaVersion": 1,
  "generator": "gen-chart/scripts/build-gallery.mjs",
  "generatorVersion": "0.9.0",
  "entryCount": 12,
  "entries": [
    {
      "id": "build-times",
      "title": "CI Build Duration by Pipeline",
      "question": "How do build times and outliers differ by pipeline?",
      "family": "distribution",
      "marks": ["boxplot"],
      "featured": true,
      "prompt": "Create a chart with gen-chart.\n...",
      "promptSha256": "...",
      "source": "gallery/sources/build-times.distribution.json",
      "artifact": "gallery/build-times.html",
      "bytes": { "source": 1234, "artifact": 60424 },
      "sha256": { "source": "...", "artifact": "..." },
      "validation": {
        "quality": "showcase",
        "errors": 0,
        "warnings": 0
      }
    }
  ]
}
```

The page is server-rendered and does not embed or fetch this manifest. This
keeps the no-JavaScript experience complete, avoids two runtime data paths,
and removes JSON-in-HTML escaping hazards. Tests instead assert that prompt
text, paths, and status rendered into each card equal the parsed manifest.

`generatorVersion` comes from `gen-chart/package.json`. Digests are lowercase
hex over exact emitted bytes. Never store absolute output paths, a
machine-dependent receipt field, or a hand-authored “passed” boolean.

## 8. Instruction-page experience

### First fold

Lead with the workflow, not a feature inventory:

> **From a prompt to a chart you can trust.**
> Copy a complete example, inspect the typed JSON it asks gen-chart to author,
> then open the chart deterministically delivered from the checked IR.

Show the complete start path:

```text
01 INSTALL  →  02 COPY PROMPT  →  03 TYPED JSON IR  →  04 INTERACTIVE CHART
```

Immediately below the introduction, add **01 Install the skill** using the
useful part of Archify's Start panel:

- one agent selector for Cursor, Codex, Claude Code, and OpenCode;
- Codex selected by default;
- one prominent **Global install (recommended)** command and Copy button;
- one secondary **Install in this repository only** command inside native
  `<details>`;
- the assurance “Same checked Skill and zero-dependency renderers—no
  vendor-specific fork”;
- a note that a new agent session may be needed after installation.

Use native radio inputs in a labelled `<fieldset>` for the mutually exclusive
agent selection. Style them as a segmented control; do not use ARIA tabs when
there is no tab panel.

The generated commands are:

````text
Global:
```bash
npx -y skills add sses79/gen-chart --skill gen-chart --agent <agent> --global --copy --yes
```

This repository only:
```bash
npx -y skills add sses79/gen-chart --skill gen-chart --agent <agent> --copy --yes
```
````

`<agent>` is exactly one of `cursor`, `codex`, `claude-code`, or `opencode`.
The browser changes only this token. In the no-JavaScript fallback, show the
existing universal command:

```text
npx skills add sses79/gen-chart -g
```

Keep installation copying separate from example prompt copying; do not add
“Copy install + prompt” in release one. Those values are used in different
places—a shell and an agent chat—and combining them makes the next action less
clear.

Do **not** add Archify's “Just describe it / Use a repository” selector.
Archify changes evidence rules and prompt wording for those paths. In
gen-chart, pasted values and workspace files already converge on the same
typed-IR workflow, so the selector would add a decision without changing the
result. The verified examples are the way users choose how to start.

After installation, introduce **02 Start from a verified example**. Render
the featured case once as the first and visually prominent card. Do not
duplicate its SVG in a hero iframe or a second card.

### Filters and URLs

Use one accessible single-select group:

- All
- Cartesian
- Distribution
- Proportion
- Heatmap

“Heatmap” is the reader-facing label for the `matrix` family. The URL value
remains the schema family:

```text
?agent=cursor|codex|claude-code|opencode&family=all|cartesian|distribution|proportion|matrix#example-<id>
```

Resolved behavior:

- Default or invalid agent: `codex`.
- Default or invalid family: `all`.
- Agent changes use `history.replaceState` and preserve the case hash. An
  explicit filter change clears the hash so the user's new filter choice wins.
- A valid case hash takes priority: if its card is excluded by the current
  family, switch to that case's family, update the URL, reveal the card, and
  move focus to the card heading. Its copy-ready prompt is already visible.
- Read query/hash state on load and re-apply case behavior on `hashchange`.
  Ignore an unknown case hash without changing the selected family.
- Use `hidden` on excluded cards so visual, keyboard, and assistive-technology
  state agree.
- Announce the visible result count in a polite `aria-live` region.

Do not add mark-level filters in this release.

### Example card

Each card renders all essential content in HTML:

```text
Question the chart answers
Title · family · marks · showcase receipt

[exact inline SVG preview]

COPY-READY PROMPT                                      COPY PROMPT
<complete, concise, selectable message>

[03 View typed JSON IR]  [04 Open interactive chart]

source sha256 abc123…  ·  artifact sha256 def456…
```

Keep the complete prompt and **Copy prompt** button visible, with a quiet
section label and top-right action like the Archify example. Put prompt text
in `<pre><code>` as escaped text content. Do not use `innerHTML` for prompts at
build time or run time.

On the two-column desktop grid, stretch each pair to the taller article so
adjacent card borders end on the same baseline. The single-column mobile grid
keeps each article at its natural height.

Each card uses `id="example-<case-id>"`; its heading link navigates to that
stable case URL. Preview links have descriptive accessible names, and external
repository links use `rel="noopener noreferrer"`.

### Progressive enhancement

With JavaScript disabled:

- all cards and prompts remain in the document;
- native details can expand;
- source and artifact links work;
- prompts can be selected and copied manually;
- hashes navigate to cards.

JavaScript adds only agent-command switching, family filtering, URL-state
restoration, one-click copy, and hash-target expansion. It must not generate
card content, fetch the manifest, or be required to understand the workflow.

Agent, Filter, and Copy controls are enhancement-only: hide elements marked
`data-js-only` by default, add a `js` class to `<html>` in the head when script
execution is available, and reveal them through `.js [data-js-only]`. This
prevents inert controls from appearing in the no-JavaScript experience. The
universal install command, cards, prompts, and links remain visible.

### Clipboard behavior

- Use `navigator.clipboard.writeText` only when available in a secure context.
- Otherwise copy from a temporary readonly textarea with
  `document.execCommand('copy')`.
- Read the copy value from that card's server-rendered prompt text.
- Change the initiating button to “Copied” briefly, then restore it.
- Announce success or failure in that card's `role="status"` region.
- Do not announce success until an API reports success.
- Never copy automatically on page load, hash navigation, or details opening.

### Accessibility and layout

- Use real buttons, links, headings, `<details>`, and `<summary>` elements.
- Filter buttons expose `aria-pressed`; copy feedback uses a polite live
  region.
- All interactive targets are at least 44 CSS pixels in their shortest
  dimension and have visible `:focus-visible` styles.
- Prompt blocks wrap or scroll internally; the page has no horizontal
  overflow at 320 CSS pixels.
- Do not add entrance animation. If motion is added later, honor
  `prefers-reduced-motion`.
- Keep current theme tokens and readable light/dark contrast.
- Keep `docs/index.html` under 150 KiB uncompressed in this release. Prompt
  text increases the previous roughly 54 KiB page to roughly 97 KiB, but no
  card adds an iframe, remote asset, or duplicate copy of its SVG.

## 10. Test strategy

### Registry and prompt unit tests

- Registry ids/specs are unique and have exact one-to-one spec coverage.
- Invalid ids, traversal paths, mismatched filename families, missing text,
  duplicate entries, and zero/multiple featured cases fail with actionable
  errors.
- Formatter snapshots cover cartesian, histogram, boxplot, proportion,
  matrix, `null`, Unicode, dates, and units.
- Formatting the same case twice is byte-identical.
- Mutating an input column changes the prompt and `promptSha256`.
- Parsed prompt data deep-equals `spec.data`; do not test brittle substring
  counts such as “every number occurs exactly once.”

### Builder and generated-output tests

- CLI delivery receipts are required and their hashes/bytes match disk.
- The staged artifact matches its committed example golden.
- Post-delivery structure rejects a missing SVG, invalid payload, unresolved
  placeholders, or external dependencies.
- Manifest order matches registry order and all digests match exact files.
- Parsed card prompt text, source/artifact links, and validation counts equal
  their manifest entries.
- Every relative link resolves inside the staged site.
- A clean build matches committed `docs/` byte-for-byte.
- A failed case leaves an existing docs fixture unchanged.
- Removing a registry case removes all of its staged outputs.
- No absolute workspace path or nondeterministic timestamp appears in output.
- The generated index stays below the release-one 150 KiB budget.

### Browser tests

- Each agent selection changes only the `--agent` token in both install
  commands and updates `?agent=`; invalid agents fall back to Codex.
- Global and repository-only install Copy buttons copy their exact visible
  commands and report success/failure accessibly.
- Filter buttons show the right cards, update `aria-pressed` and result count,
  and serialize the exact family query value.
- Invalid family state falls back to All.
- A direct case hash reveals a filtered-out card, expands its prompt, and
  focuses its heading.
- Reloading a family URL and navigating to a case hash restore state.
- Clipboard and fallback paths copy the exact server-rendered prompt and
  report success/failure honestly.
- Keyboard users can reach every workflow action and operate details/filters.
- The page has no horizontal overflow at mobile width.
- The page retains the universal install command, cards, prompts, and links—but
  no inert agent/filter/copy controls—when script execution is blocked.

Keep visual review honest: browser containment and interaction tests may pass,
but the UI must not claim a human visual review occurred.

### CI

Retain the existing production path:

```text
npm run test:ci
npm run build:gallery
git diff --exit-code -- ../docs
```

Add registry, prompt, manifest, staged-commit, and browser cases to the normal
Node test suite. Do not create a CI-only builder or a second rendering path.

## 11. Implementation slices

### Slice 1 — Content contract

- Add all 12 registry entries.
- Add the pure prompt formatter and snapshots.
- Add coverage/invariant tests.

**Exit gate:** Every example has deterministic teaching intent and an exact,
data-bearing copy-ready message; no generated files change yet.

### Slice 2 — Verified staged builder

- Deliver each case into staging through the existing CLI receipt path.
- Add post-delivery checks and golden comparison.
- Generate the versioned manifest with hashes and byte counts.
- Add transactional docs replacement and failure-preservation tests.

**Exit gate:** A failed case cannot replace last-good docs, and every emitted
source/artifact is bound to a showcase receipt and digest.

### Slice 3 — Instruction page

- Extract the template literal into `gallery-template.html` with a small,
  asserted placeholder set.
- Render the first-fold workflow, four-agent install section, filters, card
  actions, visible copy-ready prompts, and verification facts on the server.
- Add URL state and accessible copy as progressive enhancement.

**Exit gate:** With or without JavaScript, a visitor can move from an example
request to its exact IR and checked chart.

### Slice 4 — Integration and documentation

- Add browser coverage and mobile/light/dark inspection.
- Regenerate `docs/` and confirm a second build produces no diff.
- Update README, DESIGN, DEVELOPMENT, ROADMAP, and `gen-chart/SKILL.md` only
  where the implemented public workflow changes.

**Exit gate:** `npm run test:ci` passes, `npm run build:gallery` is
byte-deterministic, and all 12 published cards satisfy the acceptance matrix.

## 12. Acceptance matrix

| Requirement | Build evidence | Page evidence | Test gate |
|---|---|---|---|
| Four-agent installation | fixed allowed agent ids and command template | agent selector + global/local commands | URL, command, and copy tests |
| One lesson per example | exact registry/spec coverage | 12 ordered cards | registry test |
| Prompt contains source data | prompt data derived from parsed IR | selectable prompt + Copy | formatter deep-equality + browser copy |
| IR is inspectable | exact original bytes copied | `03 View typed JSON IR` | hash and link tests |
| Chart is checked | showcase `deliver --json` receipt | `04 Open interactive chart` + receipt facts | receipt, golden, artifact checks |
| No stale/partial publication | complete staged tree and transaction | only complete cases appear | failure-preservation + clean rebuild |
| Stable navigation | registry id and family query | filter and case deep link | URL/browser tests |
| No-JS usefulness | content rendered at build time | universal install, prompts, and links remain usable | script-disabled browser test |
| Deterministic site | no time/path/random fields | reproducible page/manifest | two builds are byte-identical |

The feature is complete only when every row passes for every registered case.
